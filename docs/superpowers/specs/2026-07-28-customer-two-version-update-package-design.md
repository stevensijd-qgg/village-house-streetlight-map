# 客户跨两版更新包设计

> 日期：2026-07-28
> 状态：用户已批准口头方案，待书面审阅

## 1. 目标

为仍在使用“上上个版本”的小白客户制作一个可直接交付的更新包，同时补齐：

- 道路路灯标注与路灯数量随道路文件保存、载入的修复；
- 面积地块独立导出和载入功能；
- 当前标准路灯道路数据：51 条道路、51 条亮化、48 条正数记录、合计 597 盏。

更新时必须保留客户现有房屋数据、照片和浏览器状态，并在覆盖道路前先备份。

## 2. 更新包内容

`04_网页程序/更新部分/` 最终只放以下交付文件：

| 文件 | 作用 | 客户操作 |
| --- | --- | --- |
| `index.html` | 最新网页主程序 | 覆盖旧文件 |
| `road-data.js` | 道路文件安全载入、校验和导出 | 新增或覆盖 |
| `area-data.js` | 面积地块备份、校验和载入 | 新增 |
| `roads.js` | 当前路灯标注标准道路文件 | 覆盖后还要在网页内手动选择载入 |
| `客户更新操作手册.docx` | 可编辑图文式手册 | 交给客户阅读 |
| `客户更新操作手册.pdf` | 固定排版交付手册 | 推荐客户阅读 |

不放入 `data.js`、照片、成品图或浏览器存档。客户原 `data.js` 和照片目录必须保留。

## 3. 客户更新流程

1. 在旧网页中点击“导出道路文件”，保存旧道路备份；再完整复制一份旧
   `04_网页程序` 文件夹作为兜底。
2. 关闭网页，把更新包中的 `index.html`、`road-data.js`、`area-data.js` 和
   `roads.js` 复制到客户原网页目录。
3. 重新打开客户原目录中的 `index.html`。
4. 在道路工具中点击“选择道路文件”，选择刚复制进去的 `roads.js`。
5. 核对摘要为 51 条道路、51 条亮化、597 盏路灯后确认载入。
6. 检查地图上的黄色亮化道路和路灯数量，再导出一份更新后的道路备份。
7. 面积数据仍保存在原浏览器中；更新后立即点击“导出地块文件”另存备份。

必须手动载入 `roads.js`，因为浏览器中的旧 `roadData_<村名>` 会优先于同目录文件；
只覆盖文件而不载入，旧的无路灯标注道路仍可能继续显示。

## 4. 手册设计

- 面向不熟悉电脑操作的客户，使用大标题、步骤编号、颜色提示框和文件清单。
- 重要按钮和数量使用醒目标识，避免使用开发术语。
- 单独设置“不要做”区域：不要覆盖 `data.js`、不要删除照片目录、不要清空浏览器数据。
- 提供更新成功检查表和失败恢复步骤。
- Word 与 PDF 内容一致；PDF 为推荐阅读版本，Word 供项目维护者后续修改。

## 5. 异常与恢复

- 摘要不是 51/51/597：取消载入，确认选择的是更新包中的 `roads.js`。
- 页面提示缺少脚本：确认三个程序脚本与 `index.html` 在同一级目录。
- 房屋或照片不显示：停止操作，恢复备份文件夹；不要用更新包替换 `data.js` 或照片。
- 道路载入失败：页面应保留原道路；可重新选择旧道路备份恢复。
- 面积数据看不到：先确认仍使用原电脑、原浏览器和原网页路径，再使用面积备份载入。

## 6. 验证标准

- 更新包只含设计清单中的 6 个文件，无 `data.js`、照片和历史道路备份。
- 三个程序文件与当前 `master` 内容一致。
- `roads.js` 规范化后为 51 条道路、51 条亮化、48 条正数记录、597 盏。
- Word 和 PDF 均能正常打开，页内无截断、重叠、乱码或敏感信息泄露。
- 手册明确写出备份、覆盖、手动载入、数量核对和失败恢复。
- `git diff --check` 通过，用户 PDF 和照片不被修改或提交。

## 7. 范围边界

- 不修改网页功能逻辑和标准数据，只整理已完成版本的交付文件。
- 不迁移已租标记和图标大小。
- 不自动清除或覆盖浏览器 localStorage。
- 不制作安装程序，不引入新的运行依赖。
