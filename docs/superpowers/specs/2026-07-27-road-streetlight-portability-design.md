# 道路路灯数据随文件保存与安全载入——设计说明

日期：2026-07-27  
状态：已通过；按 036 完成终审加固与验证

## 1. 背景与目标

当前网页可以给道路设置“有路灯”标记和路灯盏数，也会把修改写入浏览器
`localStorage`。现有“导出道路”代码实际上已经把整条道路对象序列化，因此
`lamped` 和 `lamps` 字段也在导出的 JavaScript 文件中。

问题出在导出后的启用方式：

- 网页启动时只自动读取与 `index.html` 同级、文件名恰好为 `roads.js` 的文件。
- 浏览器下载文件通常保存在“下载”目录；同名时还会自动改为 `roads (1).js`。
- 最新文件目前放在 `04_网页程序/road/` 子目录，网页不会自动读取它。
- 现有“载入文件道路”按钮没有让用户选择文件，只能重新采用页面启动时已经载入的
  `ROADS`，因而无法载入刚下载或改名的文件。
- 浏览器安全机制不允许网页在未经用户选择和授权时静默覆盖旁边的 `roads.js`。

本次修改目标：

1. 让路灯标记、路灯盏数与道路坐标一起可靠导出。
2. 让用户能从任意目录选择导出的道路文件，并安全载入到当前村浏览器存档。
3. 把最新的路灯标注版设为项目随附的标准 `roads.js`。
4. 防止数据更新工具把空村名静默生成为“示例村”，避免切换
   `localStorage` 键后看似丢失道路。
5. 保持网页双击可用、离线优先、手机兼容，不引入安装或构建依赖。

## 2. 已确认的标准道路数据

标准来源：

`04_网页程序/road/roads-路灯标注版.js`

核对结果：

- 共 51 条道路。
- 51 条均标记为 `lamped: true`。
- 48 条的 `lamps` 为正整数，合计 597 盏。
- `路灯4`、`路灯21补充` 未填写正数。
- `路灯25补充` 的 `lamps` 为 0。

实施时以该文件为标准生成同级 `04_网页程序/roads.js`，但不猜测或补填上述
3 条道路的数量。规范化后它们的 `lamps` 都明确保存为 `0`，表示“已标记该路段
有路灯，但当前盏数未录入/为 0”。界面汇总仍显示 597 盏。

## 3. 数据模型和保存规则

每条道路导出时至少保持下列字段：

```text
id       唯一道路编号
name     道路名称
type     路面类型
pts      GCJ-02 坐标点数组
lamped   是否有路灯，布尔值
lamps    路灯盏数，非负整数
```

兼容旧道路文件：

- 缺少 `lamped` 时按 `false` 处理；显式值必须是布尔值。如果 `lamps > 0`，
  最终统一为 `lamped: true`。
- 缺少 `lamps` 或值为 `null`、空字符串时按 `0` 处理。
- 显式的 `lamps` 只接受非负整数；负数、小数、无穷值和非数字使整份文件校验失败，
  导入预检会明确指出错误。
- 不改变坐标系；道路坐标继续使用 GCJ-02，导入流程不执行 BD-09 转换。

浏览器中的工作副本仍保存到：

```text
roadData_<当前村名>
```

页面启动时继续优先采用该村已经存在的浏览器工作副本，避免用随附文件静默覆盖
用户尚未导出的现场修改。随附 `roads.js` 作为首次启动和手动恢复的基准。

## 4. 用户操作流程

### 4.1 导出

“导出道路”继续下载一个双击网页可用的 JavaScript 数据文件。导出前先规范化
每条道路，使 `lamped` 和 `lamps` 都显式存在。

完成提示显示：

- 导出的道路总数；
- 有路灯路段数；
- 路灯总盏数；
- 浏览器可能把同名文件改成 `roads (1).js`；
- 如需立即在网页中启用，应使用“选择道路文件”载入；如需作为项目默认文件，
  则由维护人员备份后改名并放到 `index.html` 同级。

### 4.2 选择并载入道路文件

原“载入文件道路”功能改为真正的文件选择：

1. 用户点击按钮。
2. 浏览器打开本地文件选择器，用户可选择下载目录或任意子目录中的 `.js` 文件。
3. 程序读取文本，但不执行文件里的 JavaScript。
4. 允许导出器生成的前置单行 `//` 说明注释，但正文只接受
   `const ROADS = <JSON数组>;`，分号后只能有空白，禁止附加其他语句。
5. 完成结构和字段校验后，显示预览确认：
   - 道路总数；
   - 有路灯路段数；
   - 路灯总盏数；
   - 将写入的当前村名；
   - “覆盖前请先导出现有道路备份”的提醒。
6. 用户确认后，才把数据写入当前村的 `localStorage`，刷新道路图层、列表、统计和
   图例。
7. 用户取消、读取失败或校验失败时，不改动现有道路。

文件选择控件采用原生 `<input type="file">`，不依赖只在部分桌面 Chromium
浏览器提供的 File System Access API，保证双击打开、离线和手机浏览器仍可用。

## 5. 安全解析与校验

不得使用 `eval`、`Function` 或插入 `<script>` 的方式执行用户选择的文件。
解析器只剥离固定声明外壳，并对内部内容调用 `JSON.parse`。

载入前至少验证：

- 顶层是数组。
- 每条道路是对象。
- `id` 存在且在文件内唯一。
- `pts` 至少有两个点。
- 每个点都是两个有限数字组成的数组，纬度和经度处于合法范围。
- `lamped` 可规范化为布尔值。
- `lamps` 可规范化为非负整数。

任何一条失败都拒绝整个文件，并指出道路序号/名称和原因，禁止部分覆盖，避免
产生半成功状态。

## 6. 村名问题

当前 `data.js` 的村名为“示例村”，而项目实际村名是“何桥村”。这会导致：

- 网页标题和导出文件头显示错误；
- 道路存档键变成 `roadData_示例村`；
- 原先 `roadData_何桥村` 与新编辑数据分处两个键，看起来像道路丢失。

本次同时：

1. 将当前生成结果中的村名恢复为“何桥村”。
2. 修改“数据更新工具”，村名为空时停止生成并给出明确提示，不再回退到
   “示例村”。
3. 保留现有存档优先规则，不自动在两个村名键之间覆盖数据。
4. 在使用说明中加入一次性迁移步骤：先导出当前浏览器道路备份，再通过新的文件
   选择功能载入本次标准道路文件。

`data.js` 仍以 Excel 经数据更新工具生成的结果为准；直接修正当前生成文件只与
生成工具源头修复同时提交，避免下次生成再次复发。

## 7. 界面和兼容性

- 保留现有按钮位置与整体视觉，不进行无关重设计。
- 按钮文字改为能体现真实行为的“选择道路文件”。
- 文件选择、成功提示和错误提示使用已有页面交互风格。
- 导入成功后立即刷新地图、道路列表、路面统计、路灯统计和打印所用数据。
- 保持普通打印、A3/A1/A0、全村图和何桥村 A3×4 打印入口不变。
- 不要求联网，不新增 npm 包或构建步骤。

## 8. 测试设计

实施遵循测试驱动流程，先建立会在旧代码上失败的测试，再修改实现。

重点测试：

1. 最新标准文件核对：51 条道路、51 条有路灯、48 条正数、合计 597 盏。
2. 导入有效文件：选择非标准文件名和子目录文件后，路灯标记与盏数写入当前村
   `localStorage`，地图和统计同步更新。
3. 安全性：文件中带任意 JavaScript 时不执行并拒绝导入。
4. 原子性：重复 ID、无效坐标、少于两个点、非数组等错误不会覆盖原有道路。
5. 导出规范化：每条道路显式包含布尔 `lamped` 和非负整数 `lamps`，重新导入后
   数量不变。
6. 刷新持久化：导入或编辑后刷新页面，路灯标记和数量仍存在。
7. 村名生成：村名为空时生成失败；填写“何桥村”时输出正确村名。
8. 回归：房屋数量、道路绘制/编辑、GPS 纠偏、面积图层、普通打印和高清打印不受
   影响；页面 JavaScript 无语法错误、DOM ID 无重复、浏览器运行无异常。
9. 原型保留名：`__proto__`、`constructor`、`toString` 不能成为道路 ID；未知路面
   类型必须回退为泥路，不能读取对象原型属性。
10. 两阶段原子性：localStorage 写入失败，或写入后可见图层/统计刷新失败时，内存、
    地图、列表、统计和存档都保持/恢复旧状态，且不得显示成功提示。
11. 对象身份：导出只规范化导出副本，不替换页面正在使用的道路数组/对象；导出后
    编辑并点击图层时，弹窗必须读取同一个最新对象。
12. 真实入口：除 HTTP 测试页外，直接以 `file://` 双击打开也能载入完整页面；快速
    打印、A0 与 A3×4 测试必须实际调用打印入口并等待 `window.print`。

浏览器测试使用临时配置目录，不接触用户日常浏览器存档。测试过程中产生的数据
和下载文件放在临时目录并在结束后清理。

## 11. 036 终审加固

035 完成设计主体后，终审进一步收紧了“不产生半成功状态”的定义：

- 道路 ID 除格式与重复校验外，还拒绝 JavaScript 对象原型上的保留名称；页面道路
  图层索引与分类型统计采用无原型对象，所有路面类型读取都先做自有属性检查。
- 道路导入采用“规范化与图层预构建 → 持久化提交门槛 → 可见状态切换”的两阶段流程；
  localStorage 或后续界面更新失败时回滚地图、内存、列表、统计和存档。
- 道路导出不再重绑页面 `roads`，从而保留 Leaflet 点击闭包引用的对象身份。
- Edge/CDP helper 用文档哨兵等待真正的新文档，并增加 `file://` 启动入口；打印测试
  调用真实打印函数并等待实际 `window.print`，不再只检查手工拼出的 DOM。

标准源与项目默认 `roads.js` 在规范化后逐项序列化完全一致，仍为 51/51/48/597；
`路灯4`、`路灯21补充`、`路灯25补充` 继续明确为 `0`，未修改坐标或推测数量。
