# 面积地块独立文件迁移设计

> 日期：2026-07-28
>
> 状态：用户已批准
>
> 范围：面积地块独立导出与载入，不包含道路、已租标记和其他浏览器状态

## 1. 背景与目标

网页当前把圈地测面积结果保存在浏览器 `localStorage` 的
`areaData_<村名>` 中。复制网页文件夹、换电脑、换浏览器或清除浏览器数据时，
这些地块不会随程序文件迁移。

本次目标是在保持现有双击运行、离线优先和手机兼容的前提下，为面积地块增加
独立、可校验、可恢复的文件迁移能力：

- 在面积工具栏独立导出地块 JSON 文件；
- 从任意目录选择地块 JSON 文件；
- 校验并显示摘要后，整体覆盖当前村地块；
- 文件错误、用户取消、存储或渲染失败时不改变现有地块；
- 不改变道路文件格式和道路迁移流程。

## 2. 不在本次范围

- 不把面积地块合并进 `roads.js`。
- 不自动读取同级 `areas.json` 或其他默认面积文件。
- 不迁移已租标记、图标大小或其他浏览器状态。
- 不修改房屋数据、道路数据、照片、成品图或用户 PDF。
- 不新增服务器、构建工具或第三方依赖。

## 3. 用户操作

在现有“📐 测面积”工具栏增加：

- `💾 导出地块文件`
- `📂 选择地块文件`
- 一个仅由按钮触发的隐藏 JSON 文件输入框

### 3.1 导出

用户点击“导出地块文件”后，程序把当前村的全部地块导出为：

```text
何桥村-面积地块.json
```

页面继续把地块自动保存在当前浏览器中；导出文件只是可携带备份，不替代
`localStorage`。

### 3.2 载入

用户选择文件后，程序先完成整文件解析和校验，再显示：

- 文件村名；
- 文件内地块数量；
- 文件内总面积（平方米和亩）；
- 当前浏览器已有地块数量；
- 确认后将整体覆盖当前村地块的提示。

用户确认后才覆盖；取消时不改变任何状态。空地块文件允许载入，但必须明确提示
其会清空当前地块并再次确认。

## 4. 文件格式

文件是纯 JSON，不包含变量声明或可执行代码：

```json
{
  "format": "village-area-backup",
  "version": 1,
  "villageName": "何桥村",
  "areas": [
    {
      "id": "A1780000000000",
      "name": "村部东侧农田",
      "color": "#16a085",
      "pts": [
        [28.4, 112.89],
        [28.41, 112.9],
        [28.39, 112.91]
      ]
    }
  ]
}
```

约束：

- `format` 必须是 `village-area-backup`。
- `version` 当前只接受整数 `1`。
- `villageName` 必须与当前页面村名完全一致。
- `areas` 必须是数组。
- `id` 只接受 1～100 位字母、数字、下划线和连字符，且整文件内唯一。
- `name` 必须是字符串，去除首尾空白后最多 40 个字符。
- `color` 必须是六位十六进制颜色。
- `pts` 至少包含 3 个点；每个点必须是 `[纬度, 经度]` 两个有限数字。
- 纬度范围为 `-90～90`，经度范围为 `-180～180`。
- 坐标语义继续遵循项目现有 GCJ-02 约定，不在导入时自动纠偏。
- 文件不保存平方米、亩数或标签中心；载入后按边界坐标重新计算，避免缓存结果失真。
- 不接受 JavaScript 外壳、尾随代码或未知格式版本。

## 5. 代码边界

新增无依赖的 `04_网页程序/area-data.js`，采用与 `road-data.js` 相同的浏览器和
Node 双环境模块形式。它只负责纯数据逻辑：

- `normalizeAreas(value)`：规范化并校验地块数组；
- `parseAreaBackup(text, expectedVillageName)`：安全解析和校验 JSON 备份；
- `polygonArea(points)`：沿用现有球面多边形面积算法；
- `summarizeAreas(value)`：返回地块数量和总平方米；
- `serializeAreaBackup(value, villageName)`：生成版本 1 的纯 JSON 文件。

`index.html` 负责：

- 加载 `area-data.js`；
- 面积工具栏按钮和文件选择；
- 确认摘要；
- 当前村 `localStorage` 的原子替换；
- Leaflet 地块图层、统计和弹窗刷新；
- 下载文件。

现有面积显示统一调用 `AreaData.polygonArea`，算法和单位不改变。道路、房屋和打印
模块不调用面积文件解析接口。

## 6. 导入事务与错误处理

载入按以下顺序执行：

1. 读取用户选择的文本文件。
2. 用 `JSON.parse` 和 `AreaData` 完成整文件规范化；不使用 `eval`、
   `Function` 或动态脚本标签。
3. 在不改变当前页面的情况下，预计算摘要并验证候选地块可以建立图层。
4. 显示覆盖摘要并等待用户确认。
5. 保存旧的内存数组、原始 `localStorage` 值、图层和统计状态。
6. 以 `localStorage.setItem(AREA_KEY, ...)` 作为提交门槛。
7. 写入成功后切换内存地块、地图图层和统计。
8. 如果写入或后续可见状态更新失败，恢复旧存档、旧内存、旧图层和旧统计，
   且不显示成功提示。

任何错误只显示简短、可操作的中文提示；控制台可记录具体异常。文件输入框在处理后
清空，使用户可以再次选择同一个文件。

## 7. 兼容性与隐私

- 继续支持直接双击 `index.html` 的 `file://` 使用方式。
- 不需要 Node、Python、服务器或安装步骤。
- 使用原生文件选择器和 Blob 下载，兼容桌面与手机浏览器。
- 面积备份只包含地块编号、名称、颜色和边界坐标，不包含房主姓名、电话、房屋照片
  或已租状态。
- 客户升级包必须让 `area-data.js` 与 `index.html` 位于同一目录。

## 8. 测试与验收

### 8.1 纯数据测试

- 有效地块导出后重新解析，编号、名称、颜色和坐标逐项一致。
- 面积摘要与现有算法结果一致。
- 拒绝非法 JSON、附带代码、错误格式或版本、村名不一致。
- 拒绝重复或危险编号、错误名称、错误颜色、少于 3 个点、非数字和越界坐标。

### 8.2 浏览器测试

- 真实 `file://` 页面能加载 `area-data.js`。
- 导出内容是纯 JSON，包含正确村名和全部地块。
- 选择任意文件名后显示摘要，确认后整体覆盖并在刷新后保留。
- 取消、空文件误操作取消、坏文件和村名不一致不改变旧地块。
- `localStorage` 写入失败或图层切换失败时，存档和全部可见状态回滚。
- 连续选择同一文件仍能触发载入。

### 8.3 回归

- 道路及路灯导入、导出和跨刷新保持通过。
- 圈地新增、删除、清空、统计和弹窗保持通过。
- 快速打印、高清 A0 和何桥村 A3×4 打印保持通过。
- JavaScript 语法、DOM ID、`git diff --check` 保持通过。
